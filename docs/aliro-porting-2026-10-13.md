# Перенос полезных частей Aliro-реализаций

13 октября 2026. Безопасная первая часть переноса интегрирована в DigitalDoorKey:
ограниченный разбор CBOR и проверка подписанного Access Document. Рабочий NFC
Standard/Fast-путь, идентификаторы старых записей и Matter pairing сохранены.
Контроллер выключен; проверка на настоящем iPhone и Samsung пока не выполнена.

## Что перенесено

Из [UltraWideLock, d6e23761](https://github.com/ultrawidelock/ultrawidelock/tree/d6e23761e2ffbaee46db7ea4fd3807b0093e0659)
взят только переносимый, не выделяющий память CBOR cursor/recursive walker.
Лицензия ISC и авторство сохранены в
[`document_cbor/`](../aliro-esp32/components/DigitalDoorKey/src/aliro/document_cbor/UPSTREAM.md).
Полный SDK и драйверы в перенос не вошли.

При адаптации добавлены отказ при повторяющихся/неупорядоченных ключах,
неоднозначных integer/text aliases, неверном UTF-8, избыточных представлениях
чисел, остаточных байтах и превышении глубины 12/размера 4096 байт. Вложенный
MSO, защищённый COSE header и каждый IssuerSignedItem проверяются отдельно.

Новый локальный MIT-валидатор проверяет:

- стандартный `kid = SHA256("key-identifier" || publicKey)[0:8]`, без изменения
  прежнего `issuer_id` в NVS;
- ES256, полный P-256 device key и соответствие MSO/docType/версий;
- SHA-256 каждого возвращённого IssuerSignedItem в его namespace;
- наличие всех validity fields и TimeVerificationRequired;
- срок действия по переданному приложением времени; обязательное время при
  отсутствии часов даёт отказ. Время из самого документа не становится текущим;
- validity iteration по состоянию издателя, с отказом при отставании на 8 и более.

При росте iteration устаревшие persistent keys очищаются консервативно на границе
8; FastAuth также проверяет эту границу. State издателя и endpoint сохраняется
в необязательных полях MessagePack. Старые записи без этих полей читаются как 0.
Уже выданный Matter-ключ может пройти самостоятельную проверку Standard.

Поддерживается ограниченный вариант дат: UTC `YYYY-MM-DDTHH:MM:SSZ`.
`x5chain` отклоняется: цепочка сертификатов не проверяется этим модулем.
Неизвестные critical COSE headers также дают отказ. Это не заявление о полной
совместимости или сертификации Aliro.

## Граница разрешения доступа

Этап прав доступа и подписанного отзыва завершён отдельно 14 октября:
[новое состояние и проверки](aliro-access-policy-2026-10-14.md).
Далее сохранено описание первого порта.


Проверка целостности документа сама по себе не открывает дверь. AccessData
ещё требует интерпретации schedules, ReaderRuleIds, capabilities и critical access
extensions, а также текущей политики пользователя/отзыва. Библиотека требует
явного application callback для enrollment неизвестного endpoint, после
проверки документа и AUTH1 device signature. В нашей прошивке этот callback
не задан; отдельная проверка адаптера также отклоняет неизвестные ключи.

Таким образом, прежние разрешённые iPhone/Matter-ключи остаются рабочим путём,
а новый документ не создаёт скрытого обхода разрешений. Результат проверки
документа не отменяет Matter disabled user, удалённый credential, tombstone или
проверку актуальной версии данных перед открытием.

## Решение об архитектуре

Контекст: iPhone уже работал на стенде, а сохранённые identity/keys и Apple v9
нельзя менять без испытаний. PN532 не имеет UWB; новые альтернативы используют
другие хранилища и драйверы.

Решение: оставить DigitalDoorKey основным NFC backend, переносить небольшие
проверяемые модули с независимыми тестами, а замену backend выполнять отдельно.

| Вариант | Выгода | Ограничение | Решение |
| --- | --- | --- | --- |
| DDK + переносимый валидатор | Сохраняет старые сеансы и NVS, код проверяем | AccessData policy и PKI ещё нужны | Принят для первого этапа |
| Полная замена на esp-aliro | Официальный ESP32 SDK, API обмена и Step-up | Ядро поставляется binary `.a`; совместимость v9/NVS не доказана | Отдельный экспериментальный backend после стенда |
| Полная прошивка UltraWideLock | NFC/BLE/UWB и переносимые модули | Другие HAL, состояние и hardware; проверку доверия нельзя брать без аудита | Перенос отдельных совместимых модулей |

Последствия: в проекте появился небольшой ISC-модуль внутри MIT-компонента.
Он обозначен в THIRD_PARTY_NOTICES. Обновление не стирает flash и не переписывает
приватную историю Git. Публичный source-snapshot release остаётся отдельной
зафиксированной базой для сравнения.

## Следующие этапы

1. Стенд iPhone: первый/повторный tap, Standard/Fast, Apple v9, перезапуск,
   работа без сети, удаление credential, disabled user и повторное предоставление.
2. Samsung Wallet через имеющийся SmartThings hub: выдача ключа, NFC tap и отзыв.
   Наличие hub устраняет прежнее препятствие, но не доказывает совместимость.
3. AccessData decision и signed revocation documents: отдельная политика и
   сохраняемое состояние; затем enrollment по документам можно будет включать.
4. [esp-aliro, db6bc8ea](https://github.com/espressif/esp-aliro/tree/db6bc8ea93854b730b9163d2472dfa7bff86a280):
   API и сборочные условия подходят ESP32-S3/IDF 5.4 на уровне файлов SDK.
   Нужны PN532 exchange adapter, отдельное NVS, доказанный импорт identity/sub-ID,
   тест legacy v9 и сравнение NFC trace. В просмотренном API sub-ID есть getter;
   способ сохранить старое значение при миграции пока не подтверждён.
   SDK не подключён и не включён по умолчанию этой работой.
5. UWB: нужен дополнительный radio/board. Nordic/ST SDK рассматриваются как
   архитектурные примеры с их собственными лицензиями; их platform-specific код
   автоматически на ESP32 не переносится.

Сравнение продуктов и реализаций:
[aliro-competitors-2026-10-13.md](aliro-competitors-2026-10-13.md).

## Проверки

Финальная сборка ESP-IDF 5.4.4 / esp-matter 8d56152 успешна.
Application image: 2532416 байт; свободно 89024 байт
(3.4%) в прежнем OTA-разделе. SHA-256:
`8eed5ab5a55dab307715ddd7f8f09c019517acf17c5d6b5cc2d61d7e103feb9c`.

Полный host-набор: 13/14 executables проходят. Единственный красный executable
— тот же `aliro_ble_flow_test` с двумя известными upstream failures
(completion status и двойной Time Sync), исключённый из NFC-прошивки.
Все 17 firmware integration cases и 9 новых document validation cases проходят.
Прошивка не заливалась; реальный NFC tap ещё требуется.
Новый набор `aliro_document_validation_test` использует полноценные подписанные
CBOR fixtures, подмену digest/namespace, сроки, отсутствие часов, границу iteration,
непроверенную цепочку, усечение каждого префикса и независимый SHA-256 kid.
Он проверяет отказ enrollment без application policy. Интеграционные тесты
компилируют настоящий firmware adapter и NVS serializer.
