# Реле и уведомления Telegram

[English](access-integrations.md)

Функции используют общую панель контроллера и демо сайта. Код реализован;
на настоящем контроллере обе функции по умолчанию выключены. Рабочая прошивка
с iPhone **не заменена**. Физическое реле и реальную доставку сообщений нужно
проверить отдельно после будущего обновления.

<a id="relay-setup"></a>
## Реле: настройка по шагам

[Таблица проводов и схема реле](wiring.ru.md#реле-пример-подключения-к-gpio4)
показывают **GPIO4 → D модуля DFRobot DFR0473** и отдельную **цепь питания
замка через COM/NO**. Базовый вариант: питание модуля 5 В, управление HIGH,
R1 = 10 кОм на землю и отдельный стендовый замок 12 В, открывающийся от питания.
GPIO4 нужно выбрать явно; другой модуль должен соответствовать требованиям
совместимости в инструкции.

1. При снятом питании найдите у DFR0473 `D` (управление), `−` (GND), `+` (5 В)
   и контакты `COM`/`NO`/`NC`; `N/A` оставьте свободной.
   Проверьте совместимость входа с **3,3 В**, активный HIGH/LOW и номиналы
   питания модуля и замка.
2. Используйте схему только для подходящего примера DC-замка, открывающегося
   от питания. Подготовьте внешний источник модуля, цепь контактов и нужную
   защиту нагрузки. Работающий контроллер сейчас оставляем без изменений.
3. **После отдельно согласованного обновления прошивки** включите авторизацию
   панели в **Система → Безопасность**. Откройте **Действия → Управление реле**.
4. Выберите **GPIO реле = GPIO4**, если он свободен. Для модуля на схеме
   **Активный уровень выхода = HIGH**; LOW нужен только реальному LOW-модулю.
5. Выберите **Режим реле = Импульс открытия**, **Длительность = 1000 мс**, если
   замок допускает такой импульс. Установите **Выход реле = Включено** и нажмите
   **Сохранить настройки интеграций**. После сохранения выход неактивен.
6. Сначала проверьте индикацию и контакты реле без запитанного замка. Затем
   при снятом питании подключите рассчитанную цепь замка. На будущей проверке
   успешное NFC/Matter-открытие включает выход, таймер его отпускает, закрытие
   отменяет импульс. Отказ по ключу не должен включать реле.

**Следовать логическому состоянию** подходит только нагрузке, рассчитанной
на непрерывное включение: выход активен при логическом «открыто» и неактивен
при «закрыто». Завершение импульса не подтверждает физическое закрытие двери
и не меняет состояние Matter автоматически.

Сохранение, загрузка и выключение начинают с неактивного выхода. Сохранённое
«открыто» не включает реле при загрузке. Прежние `gpioAction*` не включают новый
драйвер. Разрешены GPIO4–7, 14–18, 21, 38 и 47 за вычетом занятых конфигурацией
платы. GPIO4 из примера должен оставаться свободным.

### Подробности реализации

Принятые изменения состояния через Matter, физические кнопки и прошедший
проверку NFC используют один выход. Проверка ключей Aliro и существующий
семиаргументный вызов Matter `SetLockState` / событие `LockOperation` сохранены.
Отклонённое изменение состояния или отказ NFC не включают реле. Отдельный
монотонный таймер завершает импульс независимо от Telegram и сети. Закрытие
отменяет импульс, новое открытие начинает его заново. Завершение импульса
**не подтверждает закрытие двери** и не меняет состояние Matter автоматически.

Прежние вкладки NFC/NeoPixel и State Triggers сохраняют старую конфигурацию.
Arduino `HardwareManager` по-прежнему исключён из этой сборки; для работающего
нативного драйвера используйте вкладку **Управление реле**.

<a id="telegram-setup"></a>
## Telegram: настройка по шагам

**Только уведомления:** изменения «открыт/закрыт» и, по желанию, отказы NFC.
Входящих команд, обязательного webhook, Mini App и отдельного запуска сервера
нет. То, что новый бот молчит после `/start`, — нормально.

### 1. Создать бота для уведомлений

1. В Telegram откройте официального [@BotFather](https://t.me/BotFather).
2. Отправьте `/newbot`, задайте отображаемое имя и свободный username,
   заканчивающийся на `bot`. Полученный **токен бота** храните как пароль.
3. Откройте **своего нового бота**, нажмите **Начать / Start** или отправьте
   `/start`. Это разрешит отправлять уведомления вам в личный чат.
   Ответ от бота сейчас не требуется.

Создание описано в [руководстве Telegram](https://core.telegram.org/bots/tutorial#obtain-your-bot-token).
Не вставляйте настоящий токен в скриншоты, GitHub, демо сайта или адресную
строку браузера. Он вводится в HTTPS-панели настоящего контроллера.

### 2. Получить числовой ID чата у себя на компьютере

В корне скачанного/клонированного репозитория выполните:

```sh
python3 scripts/telegram-chat-id.py
```

Нужен только Python 3. Вставьте токен в скрытый запрос **своего локального
терминала**. Утилита делает один HTTPS-запрос `getUpdates` с проверкой
сертификата и показывает только ID и типы чатов. Она не сохраняет токен,
не выводит имена и тексты, не отправляет сообщения, не подтверждает прочтение
обновлений и не меняет webhook/фильтры. Токен не нужно писать в самой команде
или оставлять в истории терминала.

Скопируйте ID со строкой `private`, например `424242` (это только пример).
Для группы: добавьте своего бота, отправьте `/start@username_вашего_бота`
в эту группу и повторите запуск утилиты. Скопируйте ID типа `group`/`supergroup`
**вместе с минусом**. Оставьте privacy mode включённым; боту достаточно права
отправки сообщений. Отправка в отдельные темы форума в панели не настраивается.

Если список пуст, отправьте новый `/start` и повторите запуск вручную.
При конфликте с webhook или другим получателем обновлений используйте нового
отдельного бота: утилита не удаляет существующие интеграции.
Подробности: [getUpdates](https://core.telegram.org/bots/api#getupdates)
и [privacy в группах](https://core.telegram.org/bots/faq#what-messages-will-my-bot-get).

### 3. После обновления подготовить вход и HTTPS настоящей панели

Это действия для **будущей настройки оборудования**, не для публичного демо:

1. В **Система → Безопасность** задайте логин/пароль панели, включите
   авторизацию, сохраните и войдите заново после перезагрузки.
2. Подготовьте серверный сертификат PEM для DNS-имени контроллера (при
   необходимости с цепочкой), соответствующий закрытый ключ PEM и доверенного
   браузеру издателя. Можно использовать локальный CA, которому доверяет ваше
   устройство. Несовпадение имени или недоверенный сертификат нужно исправить
   до ввода токена.
3. В доверенной локальной сети настройки включите **HTTPS**, чтобы появились
   поля сертификатов. Загрузите **Файл сертификата** и **Файл закрытого ключа**
   **до сохранения настройки HTTPS**. Для обычного входа браузером оставьте
   **Файл CA-сертификата (необязательно)** пустым: в этом сервере это CA для
   *проверки клиентского сертификата*, а не установка доверия в браузере.
4. Сохраните. После перезагрузки откройте `https://<DNS-имя контроллера из сертификата>/`
   на порту 443, войдите и убедитесь, что браузер доверяет соединению.
   Обычный HTTP и режим AP не принимают токен бота.

### 4. Включить уведомления и проверить

Откройте **Действия → Интеграция Telegram**:

| Поле панели | Что указать |
| --- | --- |
| Уведомления Telegram | Включено |
| Числовой ID чата | Свой ID личного чата/группы из шага 2 |
| Токен бота | Токен, выданный BotFather |
| Сообщать об отказах NFC-доступа | Включить, если нужны уведомления об отказах |

Нажмите **Сохранить настройки интеграций**, затем один раз **Отправить тестовое
уведомление**. Пример ожидаемого текста:

```text
Aliro A1B2C3
Telegram test notification
No door-position sensor is configured.
```

ID контроллера будет своим. Счётчик «Доставлено» увеличивается после успешного
ответа Telegram на `sendMessage`: одна постановка в очередь не равна доставке.
При будущей проверке оборудования принятые изменения «открыт/закрыт» создают
уведомления. Отказ NFC отправляется только при включённой настройке и не
активирует реле.

В публичном демо кнопки меняют **только вымышленные данные**. Поле токена
выключено: настоящие данные туда не вводятся. Сейчас можно освоить интерфейс
без контроллера и без аккаунта Telegram.

### Если что-то не работает

| Симптом | Что проверить |
| --- | --- |
| Поле токена недоступно / нужна авторизация | Настоящая панель после обновления, авторизация и фактически работающий HTTPS. В демо ввод токена специально выключен |
| Ожидание синхронизации времени | Дождитесь синхронизации часов; проверьте Интернет и DNS контроллера |
| В очереди, но «Доставлено» не растёт | Состояние Telegram, токен, ID с минусом, нажатие Start, блокировку бота и право писать в группу |
| Растёт «Пропущено» / ограничение частоты | Связь, правильность данных и пауза перед повтором; очередь не гарантирует доставку при сбое |
| Группа перестала получать после превращения в супергруппу | Заново получите её актуальный числовой ID и сохраните |

### Хранение токена и работа с сетью

Токен можно записать, но нельзя получить обратно через API. Пустое поле
сохраняет токен; явное удаление убирает его после выключения уведомлений.
Токен хранится в отдельном пространстве NVS и не выводится в журнал.
В профиле разработки NVS не зашифрован: физический доступ к flash может
раскрыть секреты. Существующие ключи, сопряжение и настройки не стираются.

Фоновый процесс использует официальный `api.telegram.org`, HTTPS с проверкой
сертификата и имени сервера, повторно используемое HTTP-соединение.
Перенаправления выключены. Очередь вмещает 16 событий, запросы идут не чаще
раза в секунду, при ошибках и 429 используется пауза. Неотправленные события
считаются пропущенными и не воспроизводятся после восстановления сети.
Для TLS нужны синхронизированные часы. Отправляются только ID контроллера
и общий текст состояния/отказа — без IP, ID ключей и криптографических данных.
Telegram получает эти события как внешний сервис после явного включения.

## Демо и API

В демо сайта используются вымышленные настройки и отдельное состояние каждого
считывателя в памяти браузера. Во вкладке **Управление реле** доступны симуляции
открытия, закрытия и отказа. Работает и прежнее касание PN532. Тестовое
уведомление создаёт виртуальную запись. События `DEMO_RELAY` и `DEMO_TELEGRAM`
попадают в общий журнал. Перезагрузка сбрасывает демо; настоящие токены
отклоняются. Запросов к GPIO, контроллеру и Telegram нет.

API контроллера:

- `GET /api/integrations`: настройки без токена и состояние; `Cache-Control: no-store`.
- `POST /api/integrations`: проверка и сохранение настроек, выход неактивен.
- `POST /api/integrations/test`: постановка уведомления в очередь без изменения замка.

Для записи нужны авторизация панели, JSON и заголовок
`X-Aliro-Request: integrations-ui`. Для записи токена дополнительно нужен HTTPS.
Размер запроса — до 2048 байт. `/api/integrations/simulate` существует
**только в адаптере демо**.

Проверки в `aliro-esp32/components/access_integrations/tests` и
`scripts/tests/controller-ui-integrations.test.mjs` охватывают исключённые GPIO,
таймер и отмену импульса, проверку настроек, скрытие/удаление токена,
отказ по ключу и изоляцию браузерных уведомлений. Компиляция и тесты браузера
не заменяют проверку физического драйвера и бота после обновления устройства.

Источники: [Telegram Bot API](https://core.telegram.org/bots/api#sendmessage),
[HTTP-клиент ESP-IDF 5.4.4](https://docs.espressif.com/projects/esp-idf/en/v5.4.4/esp32s3/api-reference/protocols/esp_http_client.html),
[GPIO ESP32-S3](https://docs.espressif.com/projects/esp-idf/en/v5.4.4/esp32s3/api-reference/peripherals/gpio.html).
